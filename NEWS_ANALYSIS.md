# Gemini news analysis

**Not financial advice.** Sentiment and impact are model interpretations of
limited source excerpts, not return forecasts or recommendations to trade.

## Inputs and output

`POST /api/refresh` fetches news, deduplicates it using Phase 1 storage, and runs
analysis for each ticker. `POST /api/news-analysis` uses only cached news and
shares the same run lock. Both return a refresh run URL immediately. The local
scheduler continues to refresh every 15 minutes during configured market hours.

The selection is the latest 12 articles in a rolling 48-hour window that mention
the ticker or company name in their headline or excerpt, sorted by publication
time and database ID. All selected articles receive an
individual assessment. The cap and excerpt length are configurable; omitted
articles are counted explicitly. Company-news providers often return unrelated
syndicated stories; exact company-name and ticker text matching excludes these
from model input but keeps them in the news archive. This conservative rule
can also exclude relevant sector context or stories using an unconfigured alias.
Provide a recognizable company name when adding a watchlist item. No importance
ranking is performed. Inputs include publisher, publication time, scope,
title, excerpt, and stable article ID. They exclude secrets and trading positions.

The JSON request includes the user's original six fields and an `evidence`
extension linking each summary, key point, risk, and classification explanation
to supplied IDs. Numeric sentiment must be finite and between -1 and 1, impact
is `low|medium|high`, and horizon is `short|medium|long` (days/weeks/months).
Neutral sentiment is a valid interpretation only when an analysis succeeds.
Missing news, a missing key or a failed generation yields no sentiment value.

The adapter uses Gemini's `generateContent` REST API over HTTPS, with
`x-goog-api-key` in a header. JSON mode and a portable schema constrain generation;
strict Pydantic validation applies the full bounds and field rules locally.
Unknown fields, incomplete/truncated/safety-blocked output, out-of-range values,
invalid enums, uncited claims, unknown/duplicate IDs, incomplete article coverage,
and selected certainty phrases are rejected. Source URLs are resolved from the
stored article records, never generated by the model.

The prompt treats excerpts as untrusted data, prohibits following embedded
instructions, and requires qualified reasoning based only on supplied material.
No model tools, URL retrieval, full-text scraping or brokerage connections exist.
These checks do not prove that a cited article supports a claim or eliminate
prompt injection and model errors. Each output includes a disclaimer; review
the cited excerpts and original articles before relying on it.

## Persistence and freshness

Migration 3 adds `news_analyses` and `llm_attempts`, preserving previous data.
Each successful immutable record stores its ticker, model, prompt version,
input hash, creation timestamp, exact input excerpts/source metadata, resolved
output, and reported token usage. The hash includes the exact prompt and both
schemas. A hash match reuses the previous record, including after a restart or
forced market refresh. Timestamps of newly retrieved identical data alone do
not justify another generation. Every attempted HTTP generation, including
retries and failures, is recorded; raw provider error bodies are not stored.

`GET /api/tickers/AAPL/news-analysis` returns:

- `data`: a result matching the current selected inputs, or null.
- `previous_analysis`: the last successful snapshot if current analysis is
  missing, stale or disabled. It is never silently substituted as current.
- `coverage`: total, excluded-without-company-mention, eligible, selected and
  omitted counts and selection policy.
- `provider_status`: news cache errors, timestamps, expiry and staleness.
- `last_error`: an active sanitized Gemini/local-budget cooldown with retry time.
- `status`: `cached`, `partial`, `stale`, `unavailable`, `insufficient_news`, or
  `disabled`. Partial means the result exists but news coverage is limited,
  excerpts are truncated, or the news providers are missing/stale/incomplete.

`data.inputs` records coverage at generation time; top-level `coverage` reflects
the current window. These can differ when omitted articles age out without
changing the selected model inputs. Archive URLs work after watchlist removal:
`GET /api/tickers/AAPL/news-analysis/1`. They are explicitly historical.

## Limits and operation

Edit `news_analysis` in `config/settings.yaml`, then restart:

| Setting | Default | Meaning |
| --- | --- | --- |
| `enabled` | true | Set false to stop all Gemini calls |
| `model` | gemini-3.1-flash-lite | Explicit model ID, no automatic paid fallback |
| `max_articles` | 12 | Most recent articles per ticker, maximum 30 |
| `max_excerpt_chars` | 1200 | Characters per article excerpt |
| `max_output_tokens` | 6000 | Generation output cap |
| `timeout_seconds` | 45 | Per-request HTTP timeout |
| `retry_attempts` | 2 | Total attempts on network/server failure |
| `min_interval_seconds` | 6 | Minimum spacing between attempt start times |
| `max_calls_per_day` | 100 | All attempts across tickers per UTC day |

429 responses persist a shared provider cooldown using Google's retry metadata;
remaining tickers do not hammer the provider. Authentication/model/request
errors pause calls for an hour. Malformed output pauses the same input for
15 minutes rather than repeatedly spending tokens to repair it. A manual
market-data `force` never bypasses these safeguards or regenerates identical
successful analyses. Restart preserves cooldowns and daily attempt counts.

If no Gemini key is configured, market data and indicators still refresh and the
run is marked partial. Interrupted calls are marked in the attempt log. Token
usage is stored only when Google returns it, and is not a dollar-cost estimate.
The local daily cap is not an account spending cap or a promise of free usage.
